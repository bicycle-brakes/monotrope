## What exists today

**The one list and what derives from it.** The Omnigent tool surface of this repository is classified in exactly one place: `scripts/omnigent_policy.py`, module `omnigent_policy`, in three disjoint dicts plus a protected-path map — `DENIED_TOOLS` (29 entries, counted from the dict literal), `ALLOWED_TOOLS` (16), `ASKED_TOOLS` (1: `sys_advise_models`), `PROTECTED_PATHS` (1: the suffix `/.omnigent/config.yaml`). From that list the module renders layer 1 — the `mcp__omnigent__<tool>` deny rules and the ask rule in `.claude/settings.json` (`layer1_rules()`, `layer1_ask_rules()`; the committed file holds the 29 prefixed deny rules at `.claude/settings.json:33-61`, the ask rule `mcp__omnigent__sys_advise_models` at line 30, and `Edit(//**/.omnigent/config.yaml)` at line 62) — and layer 2, the generated file `tools/omnigent/policy.yaml` (its header says "GENERATED by scripts/omnigent_policy.py … Do not edit"). `check()` compares the tree against the render; `write()` re-renders both files; `--surface` prints the native tool surface of the installed Omnigent (`_surface()` reads `omnigent.runner.tool_dispatch._NATIVE_RELAY_BUILTIN_TOOLS` plus the four `sys_os_*` tools from `omnigent.tools.builtins.os_env`); `--evaluate` runs events through the rendered CEL policies under Omnigent's own interpreter. The installer `tools/omnigent/install.sh` merges layer 2 per machine (not read in this session — I read only its behaviour through the tests).

**How the tests run.** `tests/test_omnigent_deny_layers.py` holds the criteria of the archived change (below). Its module-scoped fixture `omnigent_py` resolves Omnigent's interpreter via `op.omnigent_python()` and calls `pytest.skip` with a stated reason where Omnigent is not installed — the docstring says that is the CI case. Where Omnigent *is* installed, `test_the_list_matches_omnigents_native_surface` asserts exact equality in **both directions**: `surface - listed == set()` ("tools this list does not classify") and `listed - surface == set()` ("listed tools Omnigent does not offer"). The remaining tests are split between CI-safe ones that need no Omnigent (render/check equality, layer-1 settings shape, merge/installer behaviour on `tmp_path`) and offline behaviour tests that run Omnigent's own code through `--evaluate`.

**How the suite blocks.** All tests run inside the single gate `pytest` of `decisions/gates.yaml` (`command: python3 -m pytest tests/ -q -n auto`, `enforcement: block`, `floor: true`, `placement: both`, `cost: minutes`). The local runner `scripts/verify_all.sh` is cheap-first (bead coding-harness-bxxt.1): ordered by cost class, it stops at the **first blocking failure** and names every selected gate it did not run. The enforcement vocabulary is `("advisory", "report", "block")` (`ENFORCEMENT` in `scripts/ci_gates.py:45`); `report`/`advisory` "speak up without blocking" (the runner's own comment at `verify_all.sh` lines 256-258). Two further schema axes exist that a machine-dependent gate can use as declared facts today: `placement` (`hosted`/`writer`/`both`, gates.yaml schema comment lines 26-29) — the `ruleset` gate is the precedent for a gate that only makes sense on the writer machine ("the maintainer's own gh login measures it … an unreachable API is red") — and `subsets` (the `docs` subset of the draft verb).

**The drift incident this change is filed against.** `main`'s recent history contains the merge of PR #379, commit `9c386131` "fix(omnigent): deny the two tools Omnigent 0.21.0 adds (coding-harness-kw40)". Comparing the current `DENIED_TOOLS` with the first-cut table of the archived neighbour change (Omnigent 0.15.0, 27 denied), the two names the table does not have are `sys_session_message` and `ui_open_file` — that is an observed difference between two artifacts I read, not a reading of the bead, whose text I cannot open (see open questions). It runs where Omnigent is installed and skips with a stated reason where it is not (CI)." So today, on the writer machine, an Omnigent upgrade turns the blocking `pytest` gate red until the list is extended, `--write` re-renders both layers, and the maintainer re-runs `tools/omnigent/install.sh`; CI never sees the test at all because the fixture skips there.
