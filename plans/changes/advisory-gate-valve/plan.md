# Plan — advisory-gate-valve

```text
For you:     Every non-blocking gate has a dated review point and a tracking item; an expired date is visible without blocking verification.
Done when:   Schema tests reject missing or malformed valves and numeric counts, report expiry without failing, and make verify is green.
Appetite:    4 hours of phase 4 in total, repairs included — a stop, not an estimate.
Not now:     Automatically changing enforcement, blocking on expiry, or repairing the documentation corpus.
Pre-mortem:  suppose it failed: most likely because a gate receives a tracking item that does not actually own its review.
Starts unless you say stop.
```

## Build sequence and files

1. **Implementation attempt:** Change `scripts/ci_gates.py` to require the valve on `report` and `advisory`, reject it on `block`, check plain unquoted YAML dates (excluding timestamps) and the bead-id and count token forms in the spec, and raise the schema version from 3 to 4. Keep validated valve fields in normalized gate records with `until` as an ISO date string and `bead` as a string for `gates()`, `gates_at`, catalog and JSON; compute expiry against the UTC date with an injectable clock for tests, and print expired gate, date and bead only in `--check-schema`, from the validated snapshot without rereading the file. Other consumers remain silent. Unknown valve keys remain ignored.

In `docs/governance/gate-catalog.md`, describe both fields and warning-only expiry, and update the generated inventory from the gate list after the held-path edit below.
