# Plan — venv-guard

```text
For you:     Direct Python commands find the checkout's environment, and kit instances keep their existing fallback.
Done when:   The startup, missing-environment and kit regressions and make verify pass.
Appetite:    Two hours of phase 4 including repairs; stop at the limit.
Not now:     A language-neutral launcher, automatic installation or changes to the dependency lock.
Pre-mortem:  suppose it failed: most likely because an imported module restarts the wrong entry point.
Starts unless you say stop.
```

## Build sequence

1. Add a standard-library-only `scripts/venv_guard.py`, callable before third-party imports. Identify the checkout from the guard's file, not the current directory; if its `.venv/bin/python3` is usable and differs from the running environment, re-execute the original entry point with its original arguments and working directory, preserving standard streams and exit status. Avoid a loop when already in that environment. Handle module-import entry points without executing the imported file as the program.
2. For a framework checkout identified by both `pyproject.toml` and `requirements-ci.txt`, leave execution in place if the environment is absent or unusable and surface `make venv` only on a missing PyYAML, Jinja2 or pydantic dependency; preserve the failure status and unrelated errors. In a kit without these files and without `.venv`, do nothing, including on dependency failure. Do not replace an existing missing dependency diagnostic in a kit.
3. Place the guard before direct third-party imports in each file listed below, including conditional imports, except `scripts/omnigent_policy.py` as decided in Q-2; account for `scripts/kit/probe.py`'s nested directory and both direct execution and imports. Calls through `new_change.py` must retain the original caller when `plans_registry.py` invokes the guard. Do not change callers. Preserve `from __future__` placement and normal import behavior.
4. Add a standard-library AST-based test scanning all Python files under `scripts/`, including nested files, for direct imports of `yaml`, `jinja2` and `pydantic`, including `from` imports and conditional imports. Require an effective guard before each import; test the check against unguarded and reordered fixture scripts as well as the real tree. Avoid counting comments or dead guard references as a guard.
5. Exercise real subprocesses with isolated temporary checkout and kit trees, controlled interpreters and a synthetic dependency. Cover direct and imported callers, arguments, working directory, streams, status, already-active environment, unavailable environment, missing and unrelated imports, kit fallback, and kit export. No provider calls or downloads are needed.
