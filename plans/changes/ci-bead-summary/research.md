# The CI job summary lists the beads a pull request changed — Research

Phase 1 for bead coding-harness-1jg.4, read on 2026-10-14 against `origin/main`
at `3199a28`, with the tracker read through `tools/bd --readonly` (bd 1.3.0)
and `origin`'s `refs/dolt/data` at `e19aef6`. Exploration only, during the
night run; the questions below wait for the maintainer.

## Result first

- The bead asks for "the beads whose state changed between the base and the
  head of the run". The tracker has no base and head in git's sense: Dolt
  history is one line, independent of git branches, and every session pushes
  into it. A pull request's tracker writes are interleaved with every other
  session's writes, and nothing records which Dolt commit belongs to which
  pull request.
- What exists: `tools/bd diff <from> <to>` compares two Dolt commits by full
  hash (measured: 2 issues affected between two commits of 2026-10-13/14), and
  `tools/bd history <id> --json` lists Dolt commits with dates. So a
  time-window diff can be built; it is noisy by construction.
- The cheapest honest summary keys on bead **ids the pull request names**
  (body, commit messages) and shows their current state from the render the
  CI already builds (`BEAD_RENDER`). On 2026-10-14, 19 of the last 20 merged
  pull request bodies name a `coding-harness-` id; 204 of 525 non-merge
  commits on `main` since 2026-10-01 do.
- Recommended shape: a hosted-only `report` step that lists (a) the named
  beads with their state now and, where a Dolt window can be found, their
  change in it, and (b) beads changed in the window but not named — as a hint
  for house rule 4, never as a block.

## The problem and where it comes from

- The committed tracker export showed tracker changes in every pull request
  diff. It went away with bead coding-harness-1jg.3 (stage 3 of the closed
  parent coding-harness-1jg, "tracker export without double bookkeeping").
- ADR 0004 (`docs/adr/0004-tracker-render-is-the-contract.md`, section "The two
  conveniences and their successors") names the successor: the pull request
  body carries the touched beads (AGENTS.md house rule 4, "a pull request names
  in its body every bead it opens, changes or closes"), "and a CI job summary
  of the changed beads follows (bead `coding-harness-1jg.4`)".
- The pull request template already has the line
  `- Beads: <title> (<id>), opened / changed / closed`
  (`.github/pull_request_template.md`, "Evidence" block;
  `.github/PULL_REQUEST_TEMPLATE/decision.md` the same).
- Bead 1jg.4 was detached from its parent on 2026-10-11 so the parent could
  close (bead comment, 2026-10-11).

## What exists today

### The CI workflow (`.github/workflows/ci.yml`, generated)

- Generated by `scripts/ci_gates.py --generate-ci` from `decisions/gates.yaml`;
  the `ci-drift` gate fails a hand edit (ci.yml lines 3-4, 125-128). A new
  step therefore goes into the gate file or the generator, never into ci.yml.
- Job `gates` runs on `push` to `main` and on `pull_request` (ci.yml 6-20);
  checkout uses `fetch-depth: 0` because `frontmatter-current` declares
  `needs_history` (ci.yml 27-29; `ci_gates.py` `_checkout`). Merge base and
  commit dates are therefore available without a change.
- The hydration step `setup-tracker` (ci.yml 38-51; generator
  `ci_gates.py` `_tracker_hydratation`): installs the pinned bd, fetches
  `refs/dolt/data`, moves the checkout's credential header to `--global`,
  runs `tools/bd bootstrap --yes`, renders once with
  `scripts/render_beads_export.py`, and exports `BEAD_RENDER`. It is emitted
  only when a gate in the job declares `needs_tracker`.
- After hydration a full Dolt store exists in the runner, so `tools/bd diff`
  and `tools/bd history` can run there (reasoned; not measured in CI).

### The render access point (`scripts/bead_render.py`)

- `render_pfad()` returns `BEAD_RENDER` when set, else renders fresh through
  `tools/bd`; without either it raises with both ways out, and gates exit 3
  (`nicht_gemessen`). The render is the *current* state only — it has no
  history, so it cannot answer "what changed" on its own.

### The gate file (`decisions/gates.yaml`)

- Vocabulary: `enforcement` advisory / report / block; `placement`
  hosted / writer / both; `needs_tracker`, `needs_history` (file header,
  lines 10-41).
- A `hosted` gate is skipped locally, declared (`ci_gates.py` `misst_in`).
  A summary that only makes sense with `GITHUB_STEP_SUMMARY` and a pull
  request event fits `placement: hosted`, `enforcement: report`.
- There is no event condition per gate: every verify gate runs on both
  `push` and `pull_request`. A pull-request-only step needs either a script
  that does nothing outside a pull request, or a new generator feature.

### Precedent for a job summary

- `scripts/check_research_currency.py` `_append_summary` appends Markdown to
  `GITHUB_STEP_SUMMARY` when it is set and never fails over it; its tests
  clear the variable (`tests/test_research_currency.py`, "criterion 9 — the
  job summary"). That gate runs in the `drift` job with
  `continue-on-error: true`.

## Candidate approaches

1. **Named beads, current state.** Collect ids from the pull request body
   (event payload) and the commit messages `base..head`; print each with
   title and state from `BEAD_RENDER`.
   - For: no Dolt history needed; uses the one render the run already has;
     exact for what the author claims; small.
   - Against: shows state, not change; a bead the pull request changed but
     never named is invisible — exactly the gap house rule 4 is meant to
     close.
2. **Dolt time window.** Pick the last Dolt commit at or before the merge
   base's commit date and the newest Dolt commit; `tools/bd diff --json`
   between them.
   - For: shows real change, including beads nobody named.
   - Against: includes every other session's writes in the window (noise
     that grows with the age of the branch); depends on writer clocks; the
     Dolt log is reached only through `history` of some long-lived bead; a
     re-run later sees a wider window; tracker writes made before branching
     fall outside.
3. **Both, joined (recommended).** Section A: named beads with state now and,
   where the window has them, old -> new. Section B: changed in the window
   but not named — "possibly another session's write, or a missing name in
   the body".
   - For: gives the reviewer the claim and a cross-check; makes house rule 4
     visible without blocking.
   - Against: the most code; section B is advisory by nature and will show
     false hits on a busy tracker.
4. **Record the Dolt commit in git.** A commit trailer or a hook writes the
   Dolt head hash at commit time; base and head then have exact Dolt points.
   - For: no time guessing.
   - Against: needs every writer and every harness to add the trailer;
     a hook outside the repository's control; out of proportion for a P3
     convenience.

## Questions this change has to answer

- [DECISION] Which beads the summary lists: only those the pull request
  names (candidate 1), the Dolt time window (candidate 2), or both joined
  (candidate 3). Recommendation: candidate 3, with section B worded as a hint
  — it keeps the claim and the check side by side, and degrades to candidate
  1 when the window cannot be found.
- [DECISION] Whether a bead changed in the window but not named in the body
  ever turns anything red. Recommendation: never — `enforcement: report`;
  the window cannot tell this pull request's writes from another session's,
  so a block would punish parallel work (house rule 4 allows two writing
  sessions).
- [GAP] Whether the tracker that `tools/bd bootstrap --yes` builds in CI
  carries the full Dolt history (so `history` and `diff` work there), or only
  the head. One hosted run of a throwaway step settles it.
- [GAP] What `tools/bd diff` reports for a comment, a label or a dependency
  change (`coding-harness-icw` showed "modified" with no field named), and
  whether a newly created bead appears as `added`.
- [GAP] How long `tools/bd history <id> --json` takes on the hosted runner
  with ~300 entries, and whether one long-lived bead is a stable source for
  the Dolt log (a bead created later misses earlier commits).
- [DETAIL] The pull request body reaches the script through an environment
  variable set from `github.event.pull_request.body`, never interpolated into
  a `run:` line — the body is untrusted input, and `${{ }}` in a shell line
  is a script-injection path. Reason: GitHub's documented hardening rule.
  This needs a small generator feature (per-gate `env:`), or the script reads
  `GITHUB_EVENT_PATH` itself (preferred: no generator change, the payload
  file is always there).
- [DETAIL] On a `push` to `main` the script prints the commit messages'
  beads for `before..after` and no body section, and outside GitHub Actions
  it does nothing and exits 0 (`placement: hosted` already skips it locally).
- [DETAIL] Bead ids are matched with the repository's prefix
  (`coding-harness-[a-z0-9]+(\.[0-9]+)*`); ids that do not resolve in the
  render are listed as "not in the tracker" — the `dangling-beads` gate
  already blocks those in tracked files, but a body is not a tracked file.
- [DETAIL] The body is read as it was at the event; editing the body does not
  re-run CI (default `pull_request` types). The summary says which commit and
  event it describes.
