| S-1 | [AMBIGUITY] | SPEC | base | Acceptance criteria 1, 4, 5 ("logical seat"); Open decisions [DETAIL] | "Logical seat" can be read two ways. (a) It is one topic slot (topic × seat). Repository seat 2 timing out on topics 1, 2 and 4 (the pi-work-route case in `research.md`) then gets three substitute attempts, one per slot, and every other topic keeps the original model. (b) It is the seat across the whole run (finder plus topics 1–8, or topics 9–11). It then gets one substitute in total. Topics 2 and 4 stay failed and the run is incomplete, or the substitute takes over all of the seat's remaining slots. The readings differ in call count and in whether the measured failure pattern is caught at all. | Opus | open | — |
| S-2 | [AMBIGUITY] | SPEC | base | Acceptance criteria 2, 3 ("reachable") | Preparation probes lazily (`scripts/stage2_availability.py` `_Selection.fill`, `reachable`): a pool model is probed only until a seat takes it. At run time every pool model that no seat holds is therefore `not-probed` or `unreachable`. (a) "Reachable" means probed reachable at preparation. Almost no candidate then qualifies, so criterion 2 rarely applies unless preparation probes extra candidates, a preparation change the spec does not name. (b) "Reachable" means not known to be unreachable, or it is checked during the run. The run then sends a prompt to an unprobed model, or probes mid-run, which ADR 0020 point 11 forbids ("no swap, re-probe or retry"). The spec only says the swap ban must be reconciled. Either way the receipt's `max_age_seconds: 900` bounds the probe evidence, and a substitute at minute 100 relies on older evidence. | Opus | open | — |
| S-3 | [AMBIGUITY] | SPEC | base | Acceptance criteria 1–3; `model-endpoints.yaml` `research_swarm.repository_seats` | Repository seat 3 is pinned to `claude-code-plan`/`claude-haiku-5-5`, and a `--seats` choice "is never silently replaced" (ADR 0020 point 11; `fill`). (a) Every required seat, pinned and maintainer-chosen seats included, gets a substitute from the Go pool. A Haiku finder failure then launches a Go model, and the maintainer's choice is replaced mid-run. (b) Only open or pool-filled seats get a substitute. A failure of the pinned or chosen seat then still stops the run. For a model outside the pool, "next" has no position. | Opus | open | — |
| S-4 | MAJOR | SPEC | base | Acceptance criterion 3 | The spec leaves four things open. Whether the substitute may be a model another seat of the same trio already holds (preparation excludes held models). Whether two seats failing at the same time may receive the same pool model. Whether a model that already failed in this run may be chosen again. Where "next" counts from: the head of the pool (cheapest unheld) or the position after the failed model. Seat identity is `research_seat_id(endpoint, model)` and drives claim namespacing and judge scores, so a duplicate model collides with another seat. Until order and eligibility are defined, the refutation "a later eligible candidate" has nothing to test against. | Opus | open | — |
| S-5 | [AMBIGUITY] | SPEC | base | Acceptance criteria 2, 8 ("available call time") | Today a correction gets only the seat's remaining topic allowance (`remaining_topic_allowance`), and a timed-out seat has none left. (a) The substitute also gets only the remaining allowance. A timeout, the main measured failure, then never gets a substitute. (b) The substitute gets a fresh role allowance (`topics: 15`, `finders: 60` minutes), bounded only by the run deadline minus the judge reserve. The run then grows longer and the substitute competes with free slots for time. | Opus | open | — |
