## What exists today

**The pytest gate's worker count is decided in three layers, and one of them is new.** The gate `pytest` in `decisions/gates.yaml` (job `verify`, enforcement `block`, floor `true`, placement `both`) declares `python3 -m pytest tests/ -q -n auto` — pytest-xdist's one-worker-per-core mode; the plugin is pinned as `pytest-xdist==3.8.0` (dev group in `pyproject.toml`). There is no pytest configuration file at all (`[tool.pytest.ini_options]` in `pyproject.toml` holds only `pythonpath = ["."]`; no `conftest.py`, `pytest.ini`, `setup.cfg` or `tox.ini` anywhere — glob checks, this session), so `-n auto` has nothing to read besides the environment. xdist arrived with PR #168 (`perf/verify-xdist`, bead `coding-harness-d5a`, merged 2026-10-19; `docs/research/2026-10-19-night-run-plan.md`, "Starting state"; the before/after numbers 294–412 s hosted single-process and ~24 min local are recorded in `plans/changes/verify-worker-cap/research.md`, citing the 2026-10-19 handovers). A suite baseline of 520.43 s "with eight workers" at `dbef390f` stands in `plans/changes/swarm-test-speed/spec.md`, Problem.

**The local worker default (bead `coding-harness-l7sc`) is implemented in `scripts/verify_all.sh` and fully pinned by tests.** The block sits after argument parsing and the `--list` exit and before the admission supervisor (`scripts/verify_all.sh`, the section commented "The local worker default (bead coding-harness-l7sc)"): when the caller's `PYTEST_XDIST_AUTO_NUM_WORKERS` is non-empty it passes through verbatim (an empty value counts as unset); otherwise the script reads logical cores (`sysctl -n hw.logicalcpu` on Darwin, `nproc` on Linux) and memory (`sysctl -n hw.memsize` in bytes; `/proc/meminfo` `MemTotal` in KiB, converted, capped at 15 digits), validates positive decimal integers (raw readings capped at 18 digits), derives the smaller of half the cores floored (minimum 1) and memory in 2-GiB steps floored (minimum 1), and exports that; failed, malformed, zero-prefixed-zero or oversized readings degrade to the remaining bound, or to no variable at all, and never fail a run. The export happens before the admission re-exec, so the value survives into the re-executed runner and every gate child. The section `2c · The local worker default (bead coding-harness-l7sc)` of `tests/test_ci.py` pins all of it with PATH-stubbed resource tools: `test_runner_derives_worker_default_from_machine_size` (criterion 1, both platforms, memory-binds-first, odd cores, one-core floors), `test_runner_preserves_explicit_worker_value` (2, including a control run proving pass-through is distinguishable from the derived default), `test_runner_defaults_empty_worker_value` (3), `test_runner_worker_detection_degrades_without_failure` (4, twenty parametrised degradation cases), and `test_runner_worker_default_preserves_gate_verdicts` (5). A later test ("Criterion 8: timing changes no selection, no enforcement, no worker forwarding, no admission", `tests/test_ci.py`) additionally asserts the duration start record carries a forwarded override verbatim (`"workers": "3"`).

**Where the count is and is not observable.** The duration history (bead `coding-harness-1um6`, merged via PR #337 — the merge commit is in this branch's recent history per the git status snapshot) records the *setting*, not the spawned count: `scripts/verify_duration.py` writes `"workers": _worker_setting()` — the environment value or null, "unset means xdist decides" — into each `run_start` line of `verify-duration.jsonl` under `verify_lock.state_root()`, alongside `memory_pct`, commit, dirty flag, gate-file digest, job, placement and the admission context; its report prints `workers: unset (xdist decides)` for the null case. Nothing in `scripts/` parses xdist's `created: N/N workers` output (grep over `scripts/`, this session). The l7sc measurements could observe the actual count only by setting `PYTEST_ADDOPTS=-v` so quiet pytest prints its worker line (`plans/changes/verify-worker-cap/plan.md`, "Quiet-machine runs — 2026-11-01"); the first, non-quiet measurement pair was voided for exactly that gap and repeated (review rows L2-3, L4-2 in `plans/changes/verify-worker-cap/findings.md`).

**Admission context the sizing shares.** `scripts/verify_all.sh` re-execs itself through `python3 -m scripts.verify_lock` (machine-wide queue and memory admission, bead `coding-harness-p6mu`; the nested-run marker `HARNESS_VERIFY_LOCK_HELD` with its token is bead `coding-harness-1um6`'s reuse path).
