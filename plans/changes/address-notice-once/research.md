## What exists today

The name decodes through two traces in the tree. First, the go-access-point review row L6-4 (`plans/changes/archive/2026-11-06-go-access-point/findings.md`, row at findings.md:1566) reports that move notices go to stderr in the reviewer path (`run_reviewer`) and to stdout in the probe, research-seat and session paths, and its verdict reads: "rejected — an accepted limit: **one output channel for address notices belongs to bead coding-harness-zywb (notice noise)**; named in the PR". The bead's own description lives in the Dolt tracker; I read no rendered copy (house rule 2), so its exact wording is an open question, not a guess.

**The notice producer.** `scripts/stage2_go.py::assess` (module `scripts/stage2_go.py`, lines 322–379) is the single producer of notices, and it emits two kinds. A same-host path move notice: `"opencode-go/{model}: the recorded base path is {recorded}, the definition names {observed}; running on with this same-host move"` (stage2_go.py:373–379). An unrecorded-wire-api drift notice: `"opencode-go/{model}: wire api \"{api}\" has no recorded base; the record declares {declared}; running on with the definition's own base"` (`_unrecorded_api_notice`, stage2_go.py:308–319). Both strings embed the model id. That matters for any dedup: the same underlying drift (same recorded path, same observed path) produces a **different string per model id**, so exact-string dedup cannot collapse an eighteen-model drift into one line — only into one line per model. A notice never changes admission (`Assessment.admitted` is `problem is None`, stage2_go.py:111–113).

**The record the notices compare against has grown.** `model-endpoints.yaml`, `endpunkte` entry `opencode-go`, `adresse` (lines 552–566) now maps **three** wire apis: `openai-completions` basis `https://opencode.ai/inference/go/openai/v1` (gelesen 2026-10-31), `anthropic-messages` basis `https://opencode.ai/inference/go/anthropic` (gelesen 2026-11-06), `openai-responses` basis `https://opencode.ai/inference/go/openai/v1` (gelesen 2026-11-06). The `bemerkung` (lines 615–620) still records the 2026-10-31 observation that Pi's live catalog reports `https://opencode.ai/inference/go/v1` — i.e. a persistent same-host path divergence against the recorded `openai-completions` base existed at last writing. Whether the live catalog still reports that moved path today is not decidable from the tree: a catalog refresh is a network action and this phase is read-only.

**Every emission site is per-occurrence; nothing is run-scoped or record-scoped.** The sites, each with its stream and its repeat unit:

- `discover_free` (`scripts/stage2.py:2784`, print at 2827–2832): prints each `activate_overlay` notice to **stderr**, once per model per live catalog refresh; the notices are stored in the free state dict (`"notices"`, stage2.py:2910).
- `run_reviewer` (`scripts/stage2.py:3263–3266`): re-assesses the activated overlay, retains and prints each notice to **stderr**, once per model per reviewer call — per member per paid round.
- `activate_overlay` (`scripts/stage2.py:2632–2690`, notices at 2660–2665): returns one notice per assessed definition; callers print or store them.
- `_review_round` (`scripts/stage2.py:11015`–): the only `@capture_address_notices()` scope. Free-discovery notices from `state["free"]["notices"]` are written into the round notes as `Notice: {notice}.` and echoed to stderr, only on the run's first unconsumed round (stage2.py:11065–11074). Dispatch/activation notices captured during the round are appended as `Address notice: {notice}` (stage2.py:11271–11272; the exception path at 11285–11288 dedupes against notes already present). So the round record carries **two different spellings** of the same fact, and the dispatch spelling re-appears in **every** round's `loop.md` block.

## What is unclear about it

1. **The bead's exact wording.** `coding-harness-zywb`'s description lives in the Dolt tracker; unreadable in this phase. The tree's two traces (L6-4 "one output channel … notice noise"; the signal-to-noise note) say noise, but whether the bead promises one output channel, one appearance per run, one appearance per record, or all of these is an open question.
2. **What "once" scopes to.** Candidates visible in the mechanism: once per run (a run-level seen-set), once per round (already approximated by `retain_address_notices`, but re-announced every round), once per drift (collapsing the per-model strings that share recorded/observed paths into one line naming the drift), once per output channel (stdout vs stderr vs report vs record). Undecided anywhere I read; interview question.
3. **The dedup unit.** The notice string embeds the model id (`stage2_go.py:317, 376`), so exact-string dedup is per model. Whether the maintainer wants same-drift-different-model collapsed into one line (and what that line names) is unrecorded; the archived volume record shows the eighteen-line shape this produces.
4. **"Once" versus "visibly reported".** ADR 0024 decision 3 and the pinned tests (`test_notices_are_kept_and_sanitised` among others) require the notice in durable evidence and on the console. How a once-only rule coexists with that promise (first occurrence announced, later occurrences only in evidence? a count?) is not stated anywhere.
5. **Two spellings, two streams.** Free-discovery notices land in the record as `Notice: {notice}.` and dispatch notices as `Address notice: {notice}` (stage2.py:11073 vs 11272); prints go to stdout in `dispatch_go`/`probe_go`/`install`-adjacent paths and to stderr in `discover_free`/`run_reviewer`/`_review_round`. Whether unifying these is inside this bead's scope comes from L6-4's phrasing ("one output channel … belongs to bead coding-harness-zywb") but is not decided.
6. **Today's live-catalog drift.** Whether Pi's catalog still reports `/inference/go/v1` against the recorded `/inference/go/openai/v1` on 2026-11-21 is not decidable read-only; the `bemerkung`'s observation dates to 2026-10-31. The change's own urgency (how much noise a run makes today) depends on it.
7. **Class declaration.** The skeleton `research.md` frontmatter carries no `class:` key (compare the archived go-access-point `research.md` line 12 `class: feature`). Routing under ADR 0020 requires `--class`, the `research.md` header and the `spec.md` header to agree; the header currently declares nothing, so the runner's `--class` is the only declaration I can see.
8. **Terms-warning symmetry.** Terms warnings repeat per dispatch by the same mechanism (`dispatch_go` stage2.py:2256–2258, `retain_terms_warnings` 2162–2168 round-scoped). Whether this bead covers only address notices (its name says so) or sets a pattern for warnings generally is unstated.
