### What exists today

**The bead's intent, as the repository records it.** This change is the deferred one-time normalisation of existing research-file headers. The census library declares it: `scripts/research_census.py` says "It only reads; correcting existing research files is a separate change (bead coding-harness-2i7x)" (`scripts/research_census.py:4`). The archived deferring change records the hand-off: Q-4 (asked 2026-11-07, answered "Ohne Normalisierung liefern") — "the one-time normalisation of existing research files becomes its own bead with its own spec that reads producers from history", accepting that "existing research files keep their current headers until then" (`plans/changes/archive/2026-11-16-explore-provenance/decisions.md:69-82`). The same bead is named at `plans/changes/archive/2026-11-16-explore-provenance/spec.md:62-64` ("Stock files await the separate history-based correction (bead coding-harness-2i7x — normalise existing research)"), at `plans/changes/archive/2026-11-16-explore-provenance/plan.md:30-31`, and as H-100's closure target: "Seats disagree what the research header holds. … `coding-harness-2i7x` (normalise research-file headers)" (`plans/changes/ontology-relation-layer/interview-prep.md:191`). The change folder itself was opened for the bead (commit 04ebc334, `plans/changes/research-header-normalise/research.md`, frontmatter `bead: coding-harness-2i7x`; row in `plans/INDEX.md:646`).

**The metadata contract the normalisation must reach.** `metadata_problems` in `scripts/research_census.py:68-145` defines it: exactly one each of `provenance`, `produced_by`, `review`, `date`, `last_reviewed`, `updated`; no duplicate nested keys inside producer/review mappings; `provenance: ai-drafted-reviewed`; a non-empty producer list where every record has `kind: llm-session`, a `name` in the program set, a `version` that is exactly one ISO calendar date, and an optional non-empty `model`; a `review` of `{status: pending, approved_by: null, approved_at: null}`; dates ordered `date <= last_reviewed <= updated` with producer versions inside `date..updated`. The program set is `{"claude-code", "codex", "pi", "stage2-research-swarm"}` (`scripts/research_census.py:25`). The prose form of the same contract is the archived spec's "Metadata contract" term (`plans/changes/archive/2026-11-16-explore-provenance/spec.md:73-81`), which adds: "The edit stamp is the actual edit day, without inventing a historical publication or human review date."

**Publication evidence.** The census derives the producing program and day from the body, not only from the header: `publication_evidence` (`scripts/research_census.py:37-53`) accepts either the latest `## Runner exploration — DAY` heading that a preceding `Stage-2 call, DAY: explore · … endpoint NAME` line names (endpoint mapped through `stage2.producer_for`, `scripts/stage2.py:1889-1896`), or a `<!-- research-swarm/v2 (quoted) run … -->` envelope with a `## Research swarm — DAY` heading. Fenced, quoted and envelope-less examples establish nothing (`research_visible_text` masks them, `scripts/stage2.py:1319-1342`; regressions `tests/test_explore_provenance.py::test_census_ignores_commonmark_fenced_publication_examples`). When evidence exists, some producer record must match that program with `version >= ` the publication day (`scripts/research_census.py:123-131`). Generated skeleton notices in the opening are flagged on published or attributed files only (`research_opening_notices`, `scripts/stage2.py:1363-1375`, patterns derived from `scripts/new_change.py` `BODY_TEMPLATE` at `scripts/stage2.py:1345-1354`; check applied at `scripts/research_census.py:211-217`).

**Who is measured, and who is stock.** The full contract check runs on every active file that is published, carries model attribution, or declares `ai-drafted-reviewed` (`scripts/research_census.py:211`); an unpublished human-written file (such as this change's own skeleton, `provenance: human-written` with no publication) is outside the contract. "Active research" is `plans/changes/<name>/research.md` excluding `archive/` (`plans/changes/archive/2026-11-16-explore-provenance/spec.md:50-53`; the scan list `active_research_files`, `tests/test_explore_provenance.py:21-23`). A metadata-defective file is stock-exempt only when git shows it committed unchanged with its last change before the census adoption day 2026-11-10 (`last_change_day`, `scripts/research_census.py:153-172`; day recorded in `decisions/adoption.yaml` under `research-census: 2026-11-10`, read via `adoption.adopted_on`, `scripts/adoption.py:42-68`); uncommitted, modified, untracked and unreadable-history cases fail closed, and unreadable metadata is never exempt (`census_findings` with `apply_adoption`, `scripts/research_census.py:220-241`). In-file dates never decide the exemption (`tests/test_explore_provenance.py::test_census_exemption_ignores_dates_written_in_the_file`), and the exempt set only shrinks: any change from the adoption day on makes a file measured forever (`test_uncorrected_stock_only_shrinks`). One file's failure never ends the scan (`tests/test_explore_provenance.py` EP6-14 note; recursive-YAML regression).
