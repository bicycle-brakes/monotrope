| S-9 | MAJOR | SPEC | base | spec.md AC 10; Terms "Branch artefact"; decisions.md "How the branches are read" | [AMBIGUITY] AC 10 does not say which files are counted, or what one counted unit is. Reading (a): every Markdown file under `plans/changes/` on every origin branch is read, and each one with absent or unparseable frontmatter is counted. That drops the `git grep` narrowing that decisions.md prescribes. It also means one `git show` per file per branch, because every lane branch cut from main carries all of main's change folders and its archive. Reading (b): only the files `git grep` selects as candidates are parsed. A malformed file the grep does not select, such as a draft that never opens its `---` block or carries no `bead:` text, is then never read and never counted. Under reading (a) that is the "silently omitted from the count" refutation. Separately, a malformed file present on several branches could count once per (branch, path), once per path, or once per blob. A fixture with one such draft on two branches gives 0, 1 or 2 depending on the reading. | Opus | rejected — literal bead-line narrowing can miss valid YAML aliases, merge keys and escaped values, contradicting S-8 and criterion 13; all eligible files are inspected and malformed frontmatter is counted once per branch and path | — |
