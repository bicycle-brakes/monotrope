# Plan — findings-per-model

```text
For you:     See findings raised, defects accepted, questions settled and rejected per model in the morning handover.
Done when:   Both report formats agree at each named commit, gaps are visible, and make verify is green.
Appetite:    6 hours of phase 4, repairs included; a stop, not an estimate.
Not now:     Changing review execution, model selection, the ladder or the stop rule.
Pre-mortem:  suppose it failed: most likely because historical records cannot be attributed or read reliably.
Starts unless you say stop.
```

Bounded change: no design or ADR. Resolve `REV` once to a full commit, default `HEAD`, and read only committed active and archived findings; never mix lane commits. Read only the two released loop heading forms and `## Phase 6 — <who>, <date>`; identify all other finding-ID tables by heading outside the count, group phase-2a blocks, and exclude rejected-answer sections and `2a-` IDs. For each change and ID use the earliest eligible row for model and the latest for Status; ignore restatements outside eligible headings. Vendor-only legacy GLM loop reviewers use their corresponding Stage-2 call model or unattributed. Use the loop Reviewer model and, for phase 6, the nearest preceding Stage-2 call of any verb if that verb is exactly `review` and no phase-6 block intervenes; otherwise retain the row in unattributed. The source receives the change, findings file, heading, position and directly preceding call lines, and returns a model ID or unattributed; test a replacement that uses the heading alone. The shared reader owns status interpretation consistent with the vocabulary in `templates/findings.md` and duplicate resolution; distinguish missing identity from unreadable evidence.

Recognize legacy duplicate markers in Status, case-insensitively, only when followed by a row ID; retain ordinary rejected rows without IDs. Follow chains to all non-duplicate roots and credit each root, not duplicates; report missing targets and cycles as gaps. Compare new or changed rows against the merge base with `origin/main` using rename-aware `git diff -M`; allow the canonical `rejected — duplicate of <ID>` with IDs joined by ` and ` and an optional colon and reason, leaving unchanged moved rows untouched. Open contributes to raised but no outcome; leading `taken`, `fixed` and historical `closed —` mean defects accepted, `resolved`, `answered` and `in spec` mean questions settled, and `rejected` means rejected. Only `open`, `taken`, `fixed`, `closed —`, `resolved`, `answered`, `in spec`, `rejected`, and `accepted limit —` are known; accepted limit contributes only to raised. Unknown statuses, malformed rows and encoding failures are gaps.

Emit a plain table to standard output and JSON Lines to `$XDG_STATE_HOME/coding-harness/findings-per-model/main.jsonl` for main, `branches/<encoded-branch>.jsonl` under that directory for a branch, and `revisions/<full-commit>.jsonl` for a non-branch revision in the same invocation; default the state root to `~/.local/state`, encode branch names as lowercase hexadecimal UTF-8 bytes, and overwrite only that output; print the file path last. JSONL starts with `{"type":"metadata","commit":"<full hash>","complete":true}`, then one `model` record per model with `model`, `raised`, `defects_accepted`, `questions_settled`, `rejected` fields; use `model: null` for unattributed and include `finding` records with `change` and `id` for its rows. Emit `gap` records with `path`, `id` when known, and `reason`; metadata has `complete: false` for gaps. Both formats name the full commit and gaps, and gaps cause non-zero exit. Order records deterministically.

## Files and steps

1. Create `scripts/findings_reader.py` for shared row parsing, status vocabulary, legacy attribution source interface and duplicate handling.
2. Create `scripts/findings_per_model.py` for commit discovery, report aggregation, JSONL and table output; create `tests/test_findings_per_model.py` for reader, command and format tests below.
3. Create `scripts/check_finding_duplicates.py` and `tests/test_finding_duplicates.py` for the new-row duplicate gate and its historical baseline.
4. Change `Makefile` to expose `findings-per-model` with `REV`, and change `docs/orchestration.md` to require one table and cutoff for main at handover time and each unmerged change branch that gained rows that night.
5. After the accepted attempt, the orchestrator edits held paths `templates/findings.md` to define the canonical duplicate form, `decisions/gates.yaml` to register the gate, and `AGENTS.md` to require the same morning tables, including earlier branches in a lane; the attempt does not edit those paths. The orchestrator runs the targeted duplicate-gate checks after those edits.
6. Update `plans/changes/findings-per-model/plan.md` with actual phase-4 time; the runner manages findings and the plan index.

Do not edit historical findings, model configuration, review execution, or the ladder. The later event-log source and metrics consumer remain separate work. The existing runner row readers can inform the shared reader, but do not change their review behavior.

Verification: `make verify`
