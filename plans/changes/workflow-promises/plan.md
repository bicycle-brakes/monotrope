## Files and steps

1. Extend `tests/test_workflow_entry.py` with the entry tests in the
   ledger; run real Make recipes in isolated fixture trees using the
   existing scaffold fixtures and a controlled interpreter, never the
   shared tracker. Check success against direct script behavior;
   parameterize rejection cases for empty name/bead, unknown or closed
   bead, duplicate name and detached HEAD. Assert failures preserve the
   index bytes and leave no new folder. Every new test builds its own
   tree. The Makefile and `.claude/commands/` are inventory of this
   repository and do not travel with the kit, so the cases that run the
   real recipes or read the command file skip where their object is absent
   (`pytest.mark.skipif`, the idiom of `tests/test_session_scan.py`) —
   the travelling copy of this file stays green without a new
   `REIST_NICHT` entry, whose cap may only sink.
2. Add `tests/test_gate_catalog.py`: compare the real catalog inventory
   with the shared reader's rendering; counter-check missing, extra and
   duplicate rows and metadata changes using fixture gate data and catalog
   text. Independently authored expected rows must check every displayed
   field, commands versus hosted actions, and escaped pipes/newlines; a
   renderer compared only with itself cannot hold criterion 1.
3. Extend `scripts/ci_gates.py` with a deterministic `catalog_rows()`
   renderer and a `--catalog` stdout mode using `gates()`, without
   filtering job or placement. Render command and hosted action
   distinctly, escape Markdown cell content, and include every field the
   spec names: id, title, command or action, job, enforcement, floor,
   placement, reason. Keep the existing CLI modes and the generated
   workflow byte-unchanged (the ci-drift gate holds them).
4. Create `docs/governance/gate-catalog.md` with the header
   `docs/governance/` requires — the key set of `scripts/check_docs.py`
   (title, category, status, created, last_reviewed, updated, owner,
   provenance, produced_by, review, tags; provenance class
   `ai-drafted-reviewed`) — prose, an inventory between generated-block
   markers regenerated by `python3 scripts/ci_gates.py --catalog`, and an
   English `Before enabling a gate` section that summarizes the existing
   sensible/proportionate rule from the workflow, including what a check
   detects and what refutes it. No new approval or enforcement policy.
   Tests compare only the generated block, not dated frontmatter.
5. Extend `Makefile` with phony `change`, `index` and `help` targets;
   retain `verify` as the default. Check nonempty NAME and BEAD before
   invoking `python3 scripts/new_change.py` with separately quoted
   arguments passed through exported NAME and BEAD environment variables
   (`"$$NAME"`, `"$$BEAD"`), rather than interpolating their values into
   shell code. Forward failures and delegate index to
   `python3 scripts/plans_registry.py --index`. Help lists all public
   targets and the required change inputs without executing them. The
   W-6 pin in `tests/test_ci.py` holds only the two verbatim recipes, so
   it needs no change.
6. Create `.claude/commands/workflow-start.md`, a thin Markdown command
   using `$ARGUMENTS` as input: require name and `--bead`, invoke the
   existing entry script with arguments treated as data and safely
   quoted, report its output and stop on failure. No frontmatter belongs
   there (`provenance.yaml`, `.claude/commands/`). Test the command's
   delegation and usage contract and run its documented invocation against
   the scaffold fixture; live Claude Code execution is a phase-6 manual
   check, not claimed by the fixture test.
7. Update only the missing-pieces notice and the §2 catalog anchor in
   `docs/WORKFLOW.md`, dating the new measurement and preserving the
   remaining gaps; keep the file's `updated:` date current. Regenerate
   `plans/INDEX.md`. Update `plans/changes/workflow-promises/spec.md` and
   `plans/changes/workflow-promises/plan.md` for implementation status,
   ledger markers and time actually used; append implementation evidence
   to `plans/changes/workflow-promises/findings.md`, preserving previous
   records. No files are deleted.

## Criterion ledger

- 1: tests/test_gate_catalog.py::test_catalog_matches_declared_gates — a missing, extra, duplicate or inaccurate row passes comparison.
- 1: tests/test_gate_catalog.py::test_catalog_renders_commands_and_actions — a hosted action is rendered as a local command or Markdown cell content breaks a row.
- 2: tests/test_gate_catalog.py::test_catalog_drift_is_rejected — mutated catalog rows or declared metadata remain accepted.
- 3: tests/test_workflow_entry.py::test_make_change_delegates_to_scaffold — the real recipe fails to produce the direct script's scaffold, index or guidance.
- 4: tests/test_workflow_entry.py::test_make_change_rejections_preserve_tree — a rejected request succeeds or changes the folder/index state.
- 5: tests/test_workflow_entry.py::test_make_index_delegates_to_registry — a stale index stays stale or a delegate failure is hidden.
- 6: tests/test_workflow_entry.py::test_make_help_lists_targets_without_side_effects — an entry/input is absent or help invokes a mutating or verification command.
- 7: tests/test_workflow_entry.py::test_workflow_start_delegates_to_scaffold — the Markdown wrapper loses name/bead, supplies its own scaffold or omits failure handling.
- 7: not a test — the phase-6 review runs the command once in Claude Code where available; an unrun live check is reported as such.
- 8: not a test — the phase-6 review compares the dated notice with the pull request's file list and the remaining gaps; a supplied piece still listed absent, a dropped absence or an undated re-check refutes it.
- 9: not a test — the phase-6 review follows the §2 link to the English heading and reads the rule there; a dead link, the German fragment or an empty section refutes it.
