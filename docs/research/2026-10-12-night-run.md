# Night run — concept

Read on 2026-10-12 against `origin/main` at `a6b7150`. A proposal, not a
decision: it takes effect only through the change that builds it (bead
coding-harness-yuw).

## What the maintainer asked for (2026-10-12)

- Night runs become a regular part of the harness, to work off what starts
  during the day. The goal of a night is getting work done, nothing else.
- On weekdays, 15:00–17:00, everything is prepared so that autonomous agents
  can run until 08:00 the next morning.
- In the morning a handover says what was done and names the day's most
  important problems, by priority.
- ROADMAP.md plays an important role.
- No feature creep; everything is built for an ADHD brain.

## It is already planned: M3

The implementation plan names this stage
(`docs/architecture/2026-09-17-implementation-plan.md`, "W2 and M3").
Unattended operation (M3) must prove total budgets, process-group
cancellation, approval timeout, restart, remote checkpoint recovery and
complete tracker restore; it rehearses **one bounded night run and a human
morning review** before routine use. Its trial criterion: at least one
mergeable pull request per week and at most fifteen minutes of morning
review per run, over weeks with assigned night work. Abort: a control
failure, two such weeks without a mergeable result, or excessive morning
review twice returns the workflow to day operation (M2).

ADR 0010 keeps that line: "M3 qualifies unattended runs of the seven-phase
workflow"; Hermes was admitted for one recurring job *outside* the phases
(the research re-check), and "unattended change runs still wait for M3".
So the night run is M3, and this concept fills in its shape.

## How it relates to Hermes

Similar: both are agents that run while nobody watches, on a schedule, and
deliver their result as a pull request the maintainer reviews in the
morning. Different: Hermes was scoped to one job that writes one file and
never touches the tracker or code (ADR 0010); the night run works whole
changes — code, tests, tracker comments. Hermes is parked (2026-10-11).

Consequence: the night run does not need Hermes. If Hermes is unparked
later, it is one candidate to *start* the night run on schedule; that is a
later question for an ADR, not part of this concept.

## The shape, three parts

1. **Preparation, weekdays 15:00–17:00, with the maintainer.** Every
   question a queued change needs from the maintainer is answered then:
   interview answers, ADR answers, taken or rejected findings. Output: a
   queue of at most three changes, each ready to run without a question.
2. **Night, autonomous, always sequential** (maintainer, 2026-10-12). One
   change at a time, in queue order, and within it one running agent or
   model call at a time; nothing runs in parallel, so the morning handover
   reads as one line of events.
   - No merge and no decision that belongs to the maintainer.
   - Commit and push after every green step; every agent ends with a
     `Resume:` line, so a usage limit or a crash costs one step, not a night.
   - A stop (red `make verify` after two repairs, a leak-check BLOCK, a
     question only the maintainer can answer) is written down and the next
     change starts.
3. **Morning, 08:00: one page**, as the handover file
   (`docs/journal/handover/`), always the same form:
   1. The day's three most important problems, by priority.
   2. Done: the pull requests waiting for the merge.
   3. Stuck: where, and why.
   4. Which ROADMAP.md theme (Now) the night moved.

## Built for an ADHD brain

- **One entry point.** In the morning the maintainer reads one file;
  everything else is a link from it.
- **At most three.** Three changes per night, three priorities per morning,
  three Now themes in ROADMAP.md.
- **The same form every day.** Nothing to search for.
- **Done means a pull request.** Finished is what waits for the merge.
- **ROADMAP.md is the one map.** The queue is picked from its Now themes;
  a change outside Now needs a reason in the queue.

## Non-goals

- **No Kanban board, canvas or dashboard** — not in Obsidian, not as a page
  — until the simple form has held for two weeks (maintainer, 2026-10-12).
  An Obsidian daily note may link the morning handover and ROADMAP.md, as a
  view; the source stays in the repository.
- No new scheduler, service or runtime component in the first version.
- No merge by an agent, ever (ADR 0008).

## Open before routine use (M3 proofs)

Not done on 2026-10-12: total budgets, process-group cancellation, approval
timeout, restart, remote checkpoint recovery, tracker restore, the runbook
entries (backup, lost-work and recovery limits). Until they are proven, a
night run is a **rehearsal**: an orchestrating Claude Code session left
running, working a queue the maintainer set, with every result a pull
request.
